Twenty components.
Eight surfaces you can brand.

Creator+ ships content templates, not design templates. An author picks a structure and fills in fields; Brightspace renders it with a single institution-wide theme.

That theme reaches eight named surfaces — not whole components. Every card below states exactly where the university's colour will appear, and where it won't.

01
Foundations

The four knobs, and the eight surfaces they touch

These four settings are the entire visual surface the university controls. They live in the Content Styler, an admin tool, and apply to every content page in the org unit — so a faculty cannot have its own accent unless it becomes a separate org unit.

Critically, each knob affects a short, published list of surfaces rather than whole components. The lists below are D2L's, not our interpretation.

Accent

Decorative only. D2L states it is not required for accessibility.

Applies toStandard callout border · blockquote left line · blockquote large quote icon · Heading 1 underline · accordion numbered divider

Accessible accent

Sits behind white text, so it must clear contrast on its own.

Applies toJumbo callout background · timeline panel heading background · timeline panel arrow background

Header colour

Must be accessible on a white background.

Applies toHeadings 1 through 6, on every content page
Aa

Header font

Headings only. Body text is unaffected.

Applies toHeadings 1 through 6. Paragraphs and all other elements keep the platform font

Everything else is neutral, and stays neutral

Tabs, click and reveal, flip cards, carousels and hotspot markers take no theme colour at all. Do not present them in university colours — the platform will not render them that way, and the gap surfaces the first time a lecturer builds a real page.

Reaching further needs a university-hosted CSS file linked through d2l.Tools.ContentStyler.CssOverride, overriding --d2l-cplus-color-primary (accent), --d2l-cplus-color-primary-dark (accessible accent), --d2l-cplus-color-neutral-one-head (header colour) and --d2l-cplus-font-family-one (header font). That is development work. Price it separately.

03
Components

Elements

Shared across all nine: inserted elements cannot be edited on the page canvas — the author must reopen the Insert Element workflow. Selecting one offers only edit, move up, move down and delete.

Learner Instructions exists on every interactive element and should be treated as required, not optional. It is what tells a student the thing is clickable.

First, the four axes

Every component in this document is measured the same four ways. Each axis answers one question a lecturer will actually ask when they sit down to build a page.

“What can I put in it?”

Content

The words, images, video and links the lecturer supplies. Anything they type or upload.

For exampleThe heading and body text inside an accordion folder, or the image on a flip card.
Usually Open

“How can I arrange it?”

Structure

How many parts there are and how they sit together — item counts, orientation, and the layout options D2L offers.

For exampleWhether an accordion is numbered, whether tabs run across or down the side, how many slides a carousel holds.
Usually Fixed set

“Can I change how it looks?”

Visual

Colour, typeface, spacing, borders, corner radius and icons — the styling of the component itself.

For exampleThe colour of an accordion divider, the fill on an active tab, the border on a callout.
Usually Locked

“What does it do when clicked?”

Behaviour

How the component responds to a student — what expands, what animates, what plays, and what feedback appears.

For exampleWhether a folder can start already open, whether a carousel autoplays, how fast a card flips.
Usually Locked

Read the “usually” row across and you have the whole product in one line: lecturers own the content, choose from a fixed menu of structures, and control neither the look nor the behaviour. The matrix below shows where the exceptions are.

Interactive image with selectable markers. The most capable element, and the most constrained — give it two Figma frames.

Lecturer
Content
Open
Structure
Nine maximum
Visual
Marker
Behaviour
Two a11y modes
Where the theme colour appearsNowhere — but this is the one element with author-set colour. The marker colour comes from a picker the lecturer controls, independent of the institution theme. Shown in blue here, not brand orange, to make that distinction visible.

Author fills in

  • Learner instructions, or keep the supplied default
  • Image and alternative text
  • Marker placement, by clicking the image
  • Per hotspot: a name used by authors and screen readers, plus content accepting text, images, video and links
  • Marker icon and colour, from a fixed icon set

Two accessibility modes, a real decision

  • Accessible hotspots only — one micro alt tag per hotspot. Low authoring cost.
  • Fully accessible image — splits the image into a keyboard-navigable grid with a micro alt tag per cell. Higher cost, but screen-reader users get the same context.

Hard limits

  • Nine markers per image, maximum.
  • JPG and PNG only. AVIF is not supported.
  • The progress bar and viewed-ticks are automatic and cannot be switched off
Use forAnatomy, equipment, maps, annotated diagrams, artwork analysis
Not forMore than nine points, or images the university only holds as AVIF
View=author/learnerA11y=hotspots/gridMarkers=4/9

One more themed surface, and it sits outside the elements

The Heading 1 underline takes the accent colour on every content page. It is the most consistently visible brand touch in Creator+, appearing on every page rather than only where a lecturer chooses a particular element. Put it in the Foundations frame, not the element frames.

04
Formative activity

Practices

Interactive activities with immediate feedback. Every type shares a title, a short description visible only to content editors, instructions, question text, and a live preview beside the authoring form.

Two things that would sink the pitch if we get them wrong

  • Practice scores are not saved or tracked. They exist only to give the learner immediate feedback. If the university wants analytics on where students struggle, Practices are the wrong tool and they need Quizzes.
  • Sandboxed courses do not render Practices. Anyone demonstrating from a sandbox sees a blank space. Build the demo in a real course shell.

AI source restrictions

Source content must be a page, a media topic with English captions, or most file types excluding PDF. Authors can regenerate, edit the source text, or discard, and rate quality. Put the PDF exclusion on the frame — otherwise it becomes the first support ticket.

Card component

Build the spec card once, then instance it twenty times. Slots, top to bottom:

  • Number badge, name and owner
  • One-line purpose
  • Component preview — trace the SVGs on this page
  • Control gauge, four axes
  • Where the theme colour appears — the row that keeps us honest
  • Author fills in, locked, hard limits
  • Use for, not for, variant chips

Page patterns to assemble

  • Module overview — jumbo callout for outcomes, plus 67/33 with an accordion of resources
  • Lesson — prose, standard callout, click and reveal, multiple-choice practice
  • Reading — stylized quote, tabs for perspectives, accordion further reading
  • Lab or procedure — left-aligned timeline, hotspot for equipment, sequencing practice
  • Concept builder — flip cards with a sorting practice
  • Assessment prep — attention callout for weighting, accordion FAQ, multi-select practice

Governance frame

  • Alt text mandatory on every flip card, hotspot and practice image. The decorative checkbox is for genuinely decorative images only.
  • Learner instructions always filled
  • Cap interactive elements per page — three is defensible
  • One documented meaning per callout format
  • Who does what: lecturers author, admins own the four theme settings, only a developer touches CSS

Before presenting

Verify against their release

Creator+ ships on a monthly cycle and the element set differs between releases. Check every limit here against the university's own Brightspace version — particularly the Tabs accessibility warning, the nine-marker hotspot ceiling, and whether D2L's accent lists have grown since publication.
