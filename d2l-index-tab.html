What survives the save,
and what does not.

Two status columns, because in Brightspace the answer depends on where the code lives — not on what the code does. Extracted from the D2L Custom HTML capability brief; source numbering matches that document.

Page / Widget A Content HTML topic or a Custom Widget. D2L documents these as supporting complete web pages, so both a stylesheet and a script file survive here.
Editor field Everywhere else — announcements, assignment briefs, discussion prompts, quiz text, module descriptions, rubrics and feedback. The inline style attribute is the only styling mechanism.
Supported Documented by D2L, or used in D2L's own published solutions.
Partial Works, with a caveat that affects how you should use it.
Not supported Removed on save, or has no effect.
Validate No D2L source found. Test in our own tenant before relying on it.
Read this before using the tables

D2L does not publish an allow-list of permitted CSS properties or JavaScript capabilities. Only the rows citing a source are documented behaviour; everything else is marked Validate rather than guessed at. Behaviour also varies by Brightspace version, configuration and role permissions, so treat this as a test plan as much as a specification.

Styling

CSS properties32 rows

In a page or widget the browser does the work, so support is essentially browser support. In editor fields the inline style attribute is the only mechanism — which is why media queries, focus states and custom properties are impossible there.

CSS compatibility in D2L Brightspace. In an HTML topic or widget the browser does the work, so support is essentially browser support; in editor fields the only mechanism is the inline style attribute.
Property or featurePage / WidgetEditor fieldNotes
<link> to an external stylesheetSupportedRemovedThe whole design system depends on this. Host in Public Files, reference by one stable path. Sources 01, 02
<style> block in the pageSupportedRemovedFine for a genuinely one-off page. Becomes copy-paste debt at three pages. Source 01
Inline style=""SupportedFilteredThe only styling that survives in editor fields — but individual declarations can still be removed. Not all inline CSS is equal. Source 06
colorSupportedSupportedThe editor's own colour picker includes a WCAG contrast check. Source 01
background-colorSupportedSupportedCheck contrast against text at 4.5:1. Do not rely on the platform theme staying the same colour.
font-sizeSupportedSupportedUse rem in a stylesheet so learner text-size settings are honoured. Inline, px is the safest bet.
font-familySupportedSupportedThe editor exposes a Font menu that writes inline declarations. Web-safe stacks only until self-hosting is proven. Source 01
font-weight, font-style, letter-spacing, line-height, text-transformSupportedSupportedNo documented restriction. Line height of at least 1.5 for body text is a WCAG requirement.
text-alignSupportedSupportedEditor has an alignment control. Avoid justified text — it harms readability for dyslexic readers.
padding, marginSupportedPartialShorthand can be normalised on save; longhand is more predictable inline.
width, heightSupportedSupportedFixed pixel widths break the responsive content pane. Never use them in a template.
max-width, max-heightSupportedSupportedSet max-width:100% on every image, without exception.
border, border-radiusSupportedSupportedDo not use a border as the only signal for state or meaning.
box-shadow, text-shadowSupportedValidateReliable in a stylesheet. Inline behaviour in restricted fields is not documented.
display:flex and flex propertiesSupportedValidateNever use order or row-reverse to change visual sequence — it desynchronises reading order from DOM order.
display:grid and grid propertiesSupportedValidatePreferred for card layouts. repeat(auto-fit, minmax(260px,1fr)) is responsive with no media query at all.
gapSupportedValidateCleaner than margin-based spacing in grid and flex layouts.
position:relativeSupportedValidateSafe when scoped inside your own container.
position:absolutePartialValidateOnly inside a positioned parent you own. Absolute layout does not survive reflow at 320px or 400% zoom.
position:fixed, position:stickyAvoidAvoidEscapes the content pane and collides with Brightspace's own chrome and sticky headers.
z-indexPartialValidateCompetes with the platform's stacking contexts for menus and dialogs. Keep values low and scoped.
overflowSupportedValidateoverflow-x:auto is the sanctioned responsive-table fallback. Add tabindex="0" to the scroll container so keyboard users can reach it.
Custom properties (--var)SupportedNot possibleDefine on a scoped wrapper class, never on :root, so platform and Creator-era variables are not overwritten. Source 02
@media queriesSupportedNot possibleCannot be expressed in an inline attribute. This single fact is why responsive design is impossible in editor fields.
@font-faceValidateNot possibleDepends on whether font file extensions clear the platform's restricted list, and on origin behaviour between the file host and the page. Source 11
@importAvoidNot possibleBlocks rendering and pulls in an origin that may be blocked by policy. Use a single <link> instead.
:hover, :focus, :focus-visibleSupportedNot possibleA visible focus style is a WCAG requirement, so its absence in editor fields is another reason custom interactive elements do not belong there.
::before, ::afterSupportedNot possibleGenerated content is not reliably announced by assistive technology. Never put meaning in it.
transition, animation, transformSupportedNot possibleMust be wrapped in a reduced-motion guard. Nothing may flash more than three times per second.
@media (prefers-reduced-motion)SupportedNot possibleMandatory for any motion we ship. Not optional polish.
aspect-ratioSupportedValidateUse on image and iframe containers to prevent layout shift as the page loads.
user-selectValidateStrippedObserved being removed from quiz questions on save. Also an accessibility and usability problem — do not use it to prevent copying. Source 06

How to use this as a test plan

Build one page containing every row marked Validate, save it into an HTML content topic, an assignment brief, a quiz question and a custom widget, then reopen the source and compare. That single exercise converts around fifteen unknowns into settled facts, and the result becomes our own internal specification — the one D2L does not publish.
